This chart does not deploy Clair. The adapter submits the image manifest to the
Clair 4.x indexer at {{ .Values.clair.url }} and reads the vulnerability report
back, so nothing works until that endpoint is reachable from this namespace.

Clair pulls the layer blobs itself, directly from Harbor's registry, using the
per-layer URLs and the token the adapter hands it. Clair's own namespace
therefore needs a network route to that registry; the adapter's does not.

NOTE: until Clair's first updater cycle finishes, its matcher answers 202 with
an empty body and every scan stays pending. That is Clair populating its
vulnerability data, not an adapter fault; watch Clair's logs.

NOTE: /probe/ready pings the job store and asks Clair's matcher whether it holds
any vulnerability data, so a pod stays unready while either is missing.
